# Total Updater Next

Новая самостоятельная программа для проверки обновлений Total Commander и его плагинов. Она не использует исходный код, бинарные файлы или ресурсы старого Total Updater.

## Быстрый старт

1. Скачайте [portable-архив 0.8.1](release/TotalUpdater-0.8.1-win7plus.zip).
2. Распакуйте `TotalUpdater.exe` в любую папку и запустите его.
3. Программа найдёт `wincmd.ini` автоматически. При необходимости укажите файл вручную на вкладке «Настройки».
4. Нажмите «Проверить обновления». Можно проверить все найденные записи или только отмеченные.

Архив содержит ровно один файл — `TotalUpdater.exe`.

## Системные требования

* Windows 7 SP1 или новее;
* .NET Framework 4.8;
* установленный Total Commander не обязателен для запуска, но нужен для автоматического обнаружения плагинов;
* доступ в интернет требуется только в момент проверки источников или скачивания пакета.

## Что умеет программа

* Находит каталог Total Commander и `wincmd.ini` с учётом `%COMMANDER_PATH%`, `%COMMANDER_INI`, HKCU/HKLM, AppData и portable-конфигурации.
* Читает разделы `PackerPlugins`, `ListerPlugins`, `FileSystemPlugins`, `ContentPlugins` и их `*Plugins64` markers; поддерживает `RedirectSection`.
* Объединяет ANSI x86, Unicode x86 и x64 варианты одного плагина в одну логическую запись, но показывает версии каждого бинарника отдельно.
* Корректно обрабатывает формат WCX `расширение=flags,path`, имена WFX из ключа INI и относительные пути от каталога TC.
* Сравнивает версии, включая PE-формат с запятыми (`0, 8, 5, 6`) и prerelease-варианты beta/rc.
* Проверяет источники Totalcmd.net, официальный сайт Ghisler, GitHub Releases API и нестандартные HTML-страницы.
* Скачивает явно доступный и однозначно выбранный пакет в каталог загрузок. По отдельной команде может установить безопасный ZIP для уже установленного WCX/WLX/WFX/WDX.

## Обнаружение и версии плагинов

Одна строка в списке соответствует plugin family, например `fileinfo.wlx`, `fileinfo.uwlx` и `fileinfo.wlx64`. Существующие варианты находятся физически, даже если marker в `*Plugins64` отсутствует.

Если версии бинарников различаются, программа показывает «Версии вариантов плагина различаются». Такая запись не получает обычный статус обновления и не может быть скачана автоматически: сначала пользователь должен привести локальную установку к согласованному состоянию.

Для большинства файлов локальная версия определяется в порядке `FileVersion → ProductVersion → text fallback`. Особые правила задаются в каталоге по имени стратегии; сейчас это используется для FileInfo, где PE-версия `2.2.3.0` соответствует публичной `2.23`.

## Каталог обновлений

Стандартный каталог встроен в EXE и включает небольшой стартовый набор Total Commander, WCX, WLX, WFX и WDX-плагинов. Каждая запись имеет стабильный ID, aliases, одну или несколько sources с приоритетом и, при необходимости, `localVersionStrategy`.

Пользовательский каталог создаётся только по явной команде во вкладке «Локальная БД»:

* рядом с EXE в portable-режиме;
* в `%APPDATA%\TotalUpdaterNext` при обычном запуске из защищённой папки.

Запись пользовательского каталога с тем же `id` полностью заменяет встроенную. Перед применением каталог валидируется: невалидная замена не уничтожает рабочую встроенную запись. Диагностика выводится в статусе приложения.

## Источники и пакеты

`priority` определяет только технический порядок запросов. После получения ответов программа выбирает canonical-версию по уровню доверия: `ManualOverride` → `OfficialAuthor` → `OfficialTotalCommander` → `MaintainerForum` → `CommunityCatalog` → `Mirror`. Более новая версия менее доверенного источника не подменяет официальную; расхождения показываются в информации о плагине. `ManualOverride` — metadata-only запись с обязательной датой и URL доказательства: она не делает HTTP-запрос и не предоставляет пакет. Пакет выбирается только для canonical-версии: сначала у canonical source, затем у других источников той же версии по authority и только потом по priority. Конфликт источников одного уровня доверия отключает загрузку.

При обычной проверке detail-страница TotalCmd.net запрашивается, если metadata-источники не определили версию или обновлению нужен пакет. Аудит опрашивает все источники. Для новой записи `ManualOverride` используйте `provider: "manual"`, `authority: "ManualOverride"`, `purpose: "Metadata"`; старый формат распознаётся с предупреждением.

GitHub-провайдер использует Releases API, игнорирует draft, а prerelease учитывает только при `includePrerelease: true`. Для release можно указать `assetPattern`. Для pilot-записей каталог также использует официальный список Ghisler и общий metadata-index TotalCmd.net; detail-страница TotalCmd.net остаётся источником пакета и fallback.

Если найден единственный подходящий пакет, он доступен для скачивания. Combined-пакет подходит любой архитектуре. При установленной family `x86 + x64` и наличии отдельных пакетов x86/x64 программа намеренно не выбирает один из них без участия пользователя.

## Безопасная установка ZIP (0.8.1)

Отметьте одну запись с доступным обновлением и нажмите «Установить отмеченный». Ранее скачанный пакет используется повторно, только если URL, canonical-версия и SHA-256 совпадают; изменённый файл блокируется. Иначе пакет скачивается в каталог загрузок, распаковывается в `%TEMP%\TotalUpdaterNext\staging\<guid>` и проверяется. Требуются корректный `pluginst.inf`, совпадение `type` и `file` с установленным плагином, а также все уже существующие бинарные варианты family. Поле `version` необязательно; если оно указано, оно должно совпасть с canonical release. В любом случае после записи проверяется фактическая локальная версия. Путь назначения берётся из фактического расположения плагина, `wincmd.ini` не изменяется.

Перед записью программа показывает файлы для замены/добавления и место backup. Она проверяет запущенный Total Commander, возможность записи, блокировки файлов и свободное место. После записи повторно обнаруживает плагин и сравнивает версии; при ошибке запускает откат. Для ручного отката нужно отметить один плагин и нажать «Откатить выбранный плагин». Откат не трогает файлы, изменённые после установки, и проверяет восстановленную версию и архитектуры. Backup и манифест сохраняются в `%LOCALAPPDATA%\TotalUpdaterNext\backups`. После сбоя программа при запуске предлагает восстановить незавершённые транзакции; при конфликте хешей ничего автоматически не перезаписывает.

ZIP с опасными путями, ссылками, повторяющимися именами или чрезмерным объёмом отклоняется. Существующий пользовательский `.ini` не перезаписывается. Старые файлы, отсутствующие в новом пакете, не удаляются. EXE/MSI/RAR/SFX и другие форматы остаются только для скачивания; программа их не запускает. Установка новых плагинов, Total Commander, self-update и UAC elevation не реализованы. SHA-256 фиксирует целостность пакета и backup, но сам по себе не удостоверяет издателя.

## Сборка и тесты

Нужен .NET SDK с targeting pack для .NET Framework 4.8.

```powershell
dotnet build .\TotalUpdaterNext.slnx -c Release --disable-build-servers
dotnet run --project .\TotalUpdater.Next.Tests\TotalUpdater.Next.Tests.csproj -c Release --no-build
```

Консольный regression-набор покрывает конфигурацию Total Commander, discovery x86/x64, конфликты версий, Catalog v2, источники и пакеты, а также ZIP inspection, план установки, транзакцию и откат.

## Структура репозитория

* `TotalUpdater.Next` — WPF-приложение .NET Framework 4.8.
* `TotalUpdater.Next.Tests` — автономные regression-тесты без внешнего тестового фреймворка.
* `release` — portable-артефакт текущего релиза.
* `TotalUpdater.Next/Catalog/plugin-catalog.json` — встроенный seed-каталог.

Подробности внутренних компонентов также находятся в [README проекта](TotalUpdater.Next/README.md).
