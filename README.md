# Total Updater Next

Новая самостоятельная программа для проверки обновлений Total Commander и его плагинов. Она не использует исходный код, бинарные файлы или ресурсы старого Total Updater.

## Быстрый старт

1. Скачайте [portable-архив 0.10.3](release/TotalUpdater-0.10.3-win7plus.zip).
2. Распакуйте `TotalUpdater.exe` в любую папку и запустите его.
3. Программа найдёт `wincmd.ini` автоматически. При необходимости укажите файл вручную на вкладке «Настройки».
4. Нажмите «Проверить обновления». Можно проверить все найденные записи или только отмеченные.

Архив содержит ровно один файл — `TotalUpdater.exe`.

## Системные требования

* Windows 7 SP1 или новее;
* .NET Framework 4.8;
* установленный Total Commander не обязателен для запуска, но нужен для автоматического обнаружения плагинов;
* доступ в интернет требуется только в момент проверки источников или скачивания пакета.

## Что умеет программа

* Находит каталог Total Commander и `wincmd.ini` с учётом `%COMMANDER_PATH%`, `%COMMANDER_INI`, HKCU/HKLM, AppData и portable-конфигурации.
* Читает разделы `PackerPlugins`, `ListerPlugins`, `FileSystemPlugins`, `ContentPlugins` и их `*Plugins64` markers; поддерживает `RedirectSection`.
* Объединяет ANSI x86, Unicode x86 и x64 варианты одного плагина в одну логическую запись, но показывает версии каждого бинарника отдельно.
* Корректно обрабатывает формат WCX `расширение=flags,path`, имена WFX из ключа INI и относительные пути от каталога TC.
* Сравнивает версии, включая PE-формат с запятыми (`0, 8, 5, 6`) и prerelease-варианты beta/rc.
* Проверяет источники Totalcmd.net, официальный сайт Ghisler, GitHub Releases API и нестандартные HTML-страницы.
* Скачивает явно доступный и однозначно выбранный пакет в каталог загрузок. По отдельной команде может установить безопасный ZIP для уже установленного WCX/WLX/WFX/WDX.
* На вкладке «Каталог» показывает установленные и отсутствующие записи, доступную версию, источник и тип; умеет ставить новые WFX/WLX/WDX с транзакционной регистрацией в INI.

## Обнаружение и версии плагинов

Одна строка в списке соответствует plugin family, например `fileinfo.wlx`, `fileinfo.uwlx` и `fileinfo.wlx64`. Существующие варианты находятся физически, даже если marker в `*Plugins64` отсутствует.

Если версии бинарников различаются, программа показывает «Версии вариантов плагина различаются». Такая запись не получает обычный статус обновления и не может быть скачана автоматически: сначала пользователь должен привести локальную установку к согласованному состоянию.

Для большинства файлов локальная версия определяется в порядке `FileVersion → ProductVersion → text fallback`. Особые правила задаются в каталоге по имени стратегии: FileInfo преобразует PE `2.2.3.0` в публичную `2.23`, а Total7zip — PE `0, 8, 5, 6` в публичную `8.56`. Неизвестный формат остаётся неопределённым, а не объявляется development-версией.

## Каталог обновлений

Стандартный каталог встроен в EXE и содержит 931 запись Total Commander, WCX, WLX, WFX и WDX. Каждая запись имеет стабильный ID, aliases, одну или несколько sources с приоритетом и, при необходимости, `localVersionStrategy`. Большинство новых aliases сверены с именами бинарников внутри ZIP; для ряда старых плагинов добавлен только metadata-источник, без автоматической загрузки.

Если встроенное и пользовательское правило не найдено, программа проверяет индексы TotalCmd.net и Ghisler один раз за сеанс проверки. `RemoteExact` требует совпадения типа и реального имени бинарника внутри доступного ZIP. Похожее название без этого подтверждения не является совпадением. При нескольких кандидатах показывается «Найдено несколько возможных правил каталога»; обновление, загрузка и установка блокируются. Remote match не записывается в пользовательский каталог.

Пользовательский каталог создаётся только по явной команде во вкладке «Локальная БД»:

* рядом с EXE в portable-режиме;
* в `%APPDATA%\TotalUpdaterNext` при обычном запуске из защищённой папки.

Запись пользовательского каталога с тем же `id` полностью заменяет встроенную. Перед применением каталог валидируется: невалидная замена не уничтожает рабочую встроенную запись. Диагностика выводится в статусе приложения.

## Источники и пакеты

`priority` определяет только технический порядок запросов. После получения ответов программа выбирает canonical-версию по уровню доверия: `ManualOverride` → `OfficialAuthor` → `OfficialTotalCommander` → `MaintainerForum` → `CommunityCatalog` → `Mirror`. Более новая версия менее доверенного источника не подменяет официальную; расхождения показываются в информации о плагине. `ManualOverride` — metadata-only запись с обязательной датой и URL доказательства: она не делает HTTP-запрос и не предоставляет пакет. Пакет выбирается только для canonical-версии: сначала у canonical source, затем у других источников той же версии по authority и только потом по priority. Конфликт источников одного уровня доверия отключает загрузку.

При обычной проверке detail-страница TotalCmd.net запрашивается, если metadata-источники не определили версию или обновлению нужен пакет. Аудит опрашивает все источники. Для новой записи `ManualOverride` используйте `provider: "manual"`, `authority: "ManualOverride"`, `purpose: "Metadata"`; старый формат распознаётся с предупреждением.

GitHub-провайдер использует Releases API, игнорирует draft, а prerelease учитывает только при `includePrerelease: true`. Для release можно указать `assetPattern`. Для pilot-записей каталог также использует официальный список Ghisler и общий metadata-index TotalCmd.net; detail-страница TotalCmd.net остаётся источником пакета и fallback.

Если найден единственный подходящий пакет, он доступен для скачивания. Combined-пакет подходит любой архитектуре. При установленной family `x86 + x64` и наличии отдельных пакетов x86/x64 программа намеренно не выбирает один из них без участия пользователя.

## Безопасная установка ZIP

Отметьте одну запись с доступным обновлением и нажмите «Установить отмеченный». Ранее скачанный пакет используется повторно, только если URL, canonical-версия и SHA-256 совпадают; изменённый файл блокируется. Иначе пакет скачивается в каталог загрузок, распаковывается в `%TEMP%\TotalUpdaterNext\staging\<guid>` и проверяется. Требуются корректный `pluginst.inf`, совпадение `type` и `file` с установленным плагином, а также все уже существующие бинарные варианты family. Поле `version` необязательно; если оно указано, оно должно совпасть с canonical release. В любом случае после записи проверяется фактическая локальная версия. Путь назначения берётся из фактического расположения плагина, `wincmd.ini` не изменяется.

Перед записью программа показывает файлы для замены/добавления и место backup. Она проверяет запущенный Total Commander, возможность записи, блокировки файлов и свободное место. После записи повторно обнаруживает плагин и сравнивает версии; при ошибке запускает откат. Для ручного отката нужно отметить один плагин и нажать «Откатить выбранный плагин». Откат не трогает файлы, изменённые после установки, и проверяет восстановленную версию и архитектуры. Backup и манифест сохраняются в `%LOCALAPPDATA%\TotalUpdaterNext\backups`. После сбоя программа при запуске предлагает восстановить незавершённые транзакции; при конфликте хешей ничего автоматически не перезаписывает.

Состояния `RecoveryConflict` и `RollbackVerificationFailed` остаются доступными для повторного отката после устранения причины. Перед каждой заменой или удалением программа заново проверяет SHA-256 целевого файла; появившийся после preflight новый файл не перезаписывается. При конфликте установки ранее заменённые файлы откатываются, а изменённый извне файл остаётся нетронутым.

Манифест использует переходы `Prepared → Installing → Completed` для установки, `Installing → InstallConflict` при гонке и `Prepared/Installing/InstallConflict/Completed/RecoveryConflict/RollbackVerificationFailed → RollingBack → RolledBack` для отката. Из `RollingBack` возможны `RecoveryConflict` и `RollbackVerificationFailed`; после устранения причины допустим повторный переход в `RollingBack`. Для каждого файла записываются `Pending → Installing → Installed → Restored`; при восстановлении файл может перейти в `Restored` прямо из `Pending` или `Installing`. Хеши остаются главным источником истины после сбоя между изменением файла и записью состояния.

ZIP с опасными путями, ссылками, повторяющимися именами или чрезмерным объёмом отклоняется. Существующий пользовательский `.ini` не перезаписывается. Старые файлы, отсутствующие в новом пакете, не удаляются. EXE/MSI/RAR/SFX и другие форматы остаются только для скачивания; программа их не запускает. Установка Total Commander, self-update и UAC elevation не реализованы. SHA-256 фиксирует целостность пакета и backup, но сам по себе не удостоверяет издателя.

## Новая установка WFX/WLX/WDX (0.9.0)

Во вкладке «Каталог» отметьте один отсутствующий плагин WFX, WLX или WDX, проверьте источник и нажмите «Установить новый плагин». WCX остаётся update-only: для новой регистрации требуются capability flags, которые программа не угадывает. Перед установкой показываются версия, каталог, файлы, фактические INI и регистрационные ключи. Требуются ZIP с корневым `pluginst.inf` и права записи в целевые каталоги; EXE/MSI не запускаются. Плагиновые DLL также не загружаются для получения detect strings.

`[Configuration] PluginBaseDir` задаёт базовый каталог; если параметра нет, используется `<каталог TC>\plugins`. Далее добавляются `<тип>\<defaultdir>` из проверенного `pluginst.inf`. В INI создаётся запись `PluginName=<path>` для WFX или первый свободный числовой ключ для WLX/WDX. Если в ZIP есть x64 companion, в `*Plugins64` добавляется marker с тем же ключом. Для `RedirectSection` изменяется фактический INI; неправильный, отсутствующий или рекурсивный redirect блокирует установку.

Начиная с 0.9.1 состав установленного TC (`TOTALCMD.EXE`/`TOTALCMD64.EXE`) сверяется с бинарниками одной family внутри проверенного ZIP. Для x86 TC нужен x86 или Unicode-x86 вариант, для x64 TC — x64, для двух вариантов TC — оба; несовпадение даёт `ArchitectureMismatch`. Проверка повторяется перед записью. Кодировка INI сохраняется: если новое значение нельзя представить без потерь (например, кириллицу в западном ANSI), установка останавливается с `EncodingConflict` до изменения INI. При откате изменённый файл плагина даёт `RecoveryConflict`, а изменённый INI — `ConfigRecoveryConflict`; оба состояния можно повторно обработать после устранения причины.

Старые INI сохраняются побайтово в backup. Patch дописывает только нужные записи без переформатирования комментариев, порядка секций, BOM и переводов строк. Перед каждой атомарной заменой повторно проверяется SHA-256 исходного INI; чужое изменение вызывает `ConfigConflict`. Manifest v4 связывает файлы плагина, конфигурацию и backup. При сбое стартовое восстановление или ручной откат возвращает оба набора файлов; пользовательская правка INI после установки вызывает `ConfigRecoveryConflict` и никогда не затирается автоматически. При откате удаляются только созданные транзакцией файлы; посторонние файлы в каталоге остаются.

## Сборка и тесты

Нужен .NET SDK с targeting pack для .NET Framework 4.8.

```powershell
dotnet build .\TotalUpdaterNext.slnx -c Release --disable-build-servers
dotnet run --project .\TotalUpdater.Next.Tests\TotalUpdater.Next.Tests.csproj -c Release --no-build
dotnet run --project .\TotalUpdater.Next.Tests\TotalUpdater.Next.Tests.csproj -c Release --no-build -- --audit-catalog-aliases
dotnet run --project .\TotalUpdater.Next.Tests\TotalUpdater.Next.Tests.csproj -c Release --no-build -- --validate-harvest-evidence
dotnet run --project .\TotalUpdater.Next.Tests\TotalUpdater.Next.Tests.csproj -c Release --no-build -- --diagnose-sources
dotnet run --project .\TotalUpdater.Next.Tests\TotalUpdater.Next.Tests.csproj -c Release --no-build -- --audit-catalog-version-fidelity
dotnet run --project .\TotalUpdater.Next.Tests\TotalUpdater.Next.Tests.csproj -c Release --no-build -- --audit-installed-coverage '--ini=C:\Program Files\Total Commander\wincmd.ini'
```

`--audit-installed-coverage` выводит Exact, Alias, RemoteExact, Ambiguous, NotFound, процент покрытия и списки пропущенных/неоднозначных плагинов. Добавьте `--offline`, чтобы проверить только встроенный и пользовательский каталоги без сети. На проверенной установке из 48 логических записей локально сопоставлены 44 (91,7%); MultiArc, Cloud, IECache и ReadPE оставлены без автоматического сопоставления из-за недостаточных доказательств источника.

`--audit-catalog-version-fidelity` опрашивает источники полного встроенного каталога и читает доступные ZIP в памяти (не устанавливает и не сохраняет их). Для каждой записи выводятся canonical-источник и версия, authority, найденные aliases, локальная PE/нормализованная версия и категория проблемы. Отсутствие пакета, недоступность источника и несовпадение бинарников различаются. Сетевые результаты зависят от доступности сайтов; диагностические находки не считаются успешной проверкой пакета. Harvest evidence проверяется в CI на повторяющиеся ID/aliases, URL, тип и дату; записи старше 180 дней получают предупреждение.

Кнопка «Проверить доступность источников» и `--diagnose-sources` выполняют отдельные bounded-проверки `totalcmd.net index`, `totalcmd.net pages`, `ghisler.com` и `GitHub API`, показывая PASS/FAIL и время ответа. В сводке обновлений недоступный shared-host указывается один раз; в строке плагина сетевой сбой не выдаётся за отсутствие записи каталога, metadata-only или неизвестную версию.

Ссылка на архив до проверки его содержимого имеет состояние `Unverified`. После загрузки ZIP без ожидаемого alias программа запрещает установку; перед самой установкой соответствие проверяется повторно. Если версия известна, но подходящего архива нет, статус показывает «Версия известна, пакет не найден»; недоступный источник показывается отдельно.

Консольный regression-набор покрывает конфигурацию Total Commander, discovery x86/x64, конфликты версий, Catalog v2, источники и пакеты, а также ZIP inspection, план установки, транзакцию и откат.

## Структура репозитория

* `TotalUpdater.Next` — WPF-приложение .NET Framework 4.8.
* `TotalUpdater.Next.Tests` — автономные regression-тесты без внешнего тестового фреймворка.
* `release` — portable-артефакт текущего релиза.
* `TotalUpdater.Next/Catalog/plugin-catalog.json` — встроенный seed-каталог.
